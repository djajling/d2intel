# BASELINE.md — первый baseline и протокол оценки моделей

Статус: **prior baseline выполнен на реальных данных**; LR-часть `ML-001` ждёт
признаков `FEAT-001`. Этот документ — протокол, по которому любая модель
сравнивается с обязательным нижним ориентиром, а не описание «результата».

Связанные документы: `docs/EVALUATION.md` (когорта, часы доступности, метрики),
`docs/adr/ADR-006-model-acceptance-threshold.md` (порог приёмки), манифест
заморозки `docs/frozen_split_<date>.json`.

## 2. Протокол оценки (обязателен для любой модели)

1. **Заморозка раньше обучения.** Сначала `scripts/freeze_split.py`, потом
   любой фит. Манифест — в `docs/`, хэш — в отчёте.
2. **Фит только на train.** Все оценки, все трансформации — на данных строго
   до `training_cutoff = valid_from - embargo`. `valid` — для настройки,
   `test` — итоговый гейт.
3. **Группировка по сериям.** Одна серия — одна группа; bootstrap
   пересэмплирует серии, не карты (`grouped_bootstrap_interval`).
4. **Обязательный floor в каждом отчёте:**
   - `majority_class_accuracy` на сегменте — точность тривиального прогноза;
   - `log_loss_uniform_reference` = ln 2 — «ничего не знаю»;
   - метрики самой модели рядом, не вместо.
5. **Достаточность выборки.** `< 30` наблюдений → вердикт
   `insufficient evidence`, заявлений о значимости нет (BACKLOG §2,
   `sample_size_verdict`).
6. **Порог 0.70** — предзарегистрированная величина из ADR-006. Она не
   является обещанием и не может быть целью подбора: подходящая модель
   сравнивается с ней на замороженном test, непрохождение фиксируется как
   факт, после чего выносится решение владельца.

## 4. Результат prior baseline на замороженном test

Модель: `prior_const`, `feature_schema_version = none.v1`,
`p_a = 0.5131` (доля побед Team A на train, `fitted_n = 3212`).

| Метрика | valid (n=110) | test (n=131) |
|---|---|---|
| accuracy (hard label prior) | 0.5364 | **0.5191** |
| log_loss prior | 0.6916 | **0.6925** |
| Brier prior | 0.2492 | **0.2497** |
| majority_class_accuracy (floor) | 0.5364 | 0.5191 |
| log_loss «p=0.5» (reference) | 0.6931 | 0.6931 |
| bootstrap log_loss (95%, по сериям) | 0.6868 … 0.6963 | 0.6881 … 0.6969 |

Вердикт: **threshold 0.70 not met (0.5191)**. Это ожидаемо и не является
отрицательным результатом — prior по построению несёт ровно одну величину
(частоту побед Team A на train) и не может преодолеть порог без признаков.
Его роль — быть измеренным floor-ориентиром и первым концом сквозной цепочки
записи предсказаний.

Записано в БД: 1 `model_version`, 131 `prediction`, 131 `prediction_snapshot`,
131 `prediction_evaluation` (режим `retrospective_reconstructed`). Перезапуск
скрипта идемпотентен — дублей нет.

## 5. Что значит «70%» в реальности

Baseline на этом target — **0.52**. Порог 0.70 — это **+18 п.п.** к
тривиальному прогнозу на задаче, где отсутствуют: составы (нужны
`/api/matches/{id}`), драфт (`picks_bans`), свежая форма команды, турнирный
контекст. То, что осталось — каноническая идентичность команд и календарь.

План движения к порогу (без подгонки под него):

1. `FEAT-001` — prior-form as-of датасет (делегировано второму агенту).
2. `TEAM-001` — командный рейтинг as-of, фит только на train.
3. `ML-001` — LR на признаках, тот же протокол, тот же замороженный test.
4. `ML-002` — CatBoost challenger; выбор делается на tuning folds,
   untouched test — только итоговый гейт.

Если на этапе 3–4 метрика не дотягивает до 0.70, так и фиксируется:
`threshold not met` + причина (мало признаков / мало данных / target
плохо отделим). Никакого подбора под test.

## 6. Известные ограничения (переносятся в любой отчёт)

- **Retrospective cutoff = `event_time`**, а не реальное время объявления
  fixture'ов: источник его не сообщает. Это **не консервативная** оценка —
  см. `docs/EVALUATION.md` §«Два часа доступности».
- Когорта ограничена данными OpenDota `/api/proMatches`: нет игроков, нет
  драфта.
- 131 наблюдение в test: интервал считается, но интерпретируется как грубая
  неопределённость, не как тест значимости.
- Замороженный test включает матчи вплоть до 2026-09-22 — недавние игры могут
  ещё дозаполняться источником; хэш манифеста это отслеживает.
