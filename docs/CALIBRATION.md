## CAL-002: результат

Champion LR (C=0.01, протокол ML-001/002) → вероятности на test. Калибраторы
фнтся **только** на calibration (76 строк); метод выбирается 2-фолдным
cross-fitting внутри неё; test читается один раз для метрик до/после.

| Метрика на test (n=140) | До калибровки | После Platt |
|---|---|---|
| log_loss | **0.6877** | 0.7251 |
| Brier | **0.2473** | 0.2649 |
| ECE (10 бинов) | **0.0478** | 0.0949 |
| accuracy | **0.5643** | 0.5071 |

Cross-fit выбор: Platt mean log_loss 0.680 vs isotonic 1.616 — изотоник на 76
строках катастрофически переобучается (fold log_loss до 2.5). Platt выбран
корректно по правилу, но на test переносится хуже сырых вероятностей.

## Вердикт

1. **Калибровка отклоняется** на текущем этапе: сырые вероятности LR уже
   хорошо откалиброваны (ECE 0.048 на test, 0.017 на прогонах ML-001), а
   Platt, обученный на 76 строках более раннего периода, вносит искажение
   (test — август-сентябрь, другой патч/мета).
2. Это ожидаемое следствие малой calibration-выборки: перекалибровка имеет
   смысл при сотнях+ строк. Порог повторного прогона — когда покрытие
   player-признаков и объём valid заметно вырастут.
3. Никаких snapshots с калиброванной вероятностью в БД не пишется; реестр
   моделей не загрязняется. CAL-003 (freeze + версия калибровки в снимках)
   стартует только после прогона с положительным эффектом.

## Известное ограничение

C champion'а выбирался на полном valid (протокол ML-001/002), то есть
calibration-строки участвовали в выборе C. Строгая ревизия — выбор C только
на tuning-части — фиксируется здесь как обязательное условие следующего
калибровочного прогона.
