## Признаки (реализованы)

`src/d2intel/features/roster.py` → интегрированы в `PriorFormBuilder` (13
колонок с ревизии 4 manifest):

- `d_roster_days_since_last` — давность последнего свидетельства;
- `d_roster_changes_30d` — приток новых игроков за 30 дней;
- `d_roster_standin_share_30d` — доля `is_standin` в окне (считается только
  по известным флагам: NULL — «нет данных», не «0%»; при <3 свидетельствах —
  `None`); на текущих данных — NaN всюду.

Fallback: нет свидетельств → NaN + маска `roster_avail=False`.

   ухудшается на 0.031. Причина честная — 71% примеров с NaN-признаками и
   нулевым сигналом стендинов.
2. **Champion остаётся LR на 9/10 prior-form признаках**; ростерные колонки
   исключаются из рабочих прогонов до роста покрытия.
3. Пересмотр — вместе с ML-002 ревизией 5, когда backfill поднимет покрытие
   (сейчас 29.3% player / 29% roster, дневные батчи продолжаются); если к
   покрытию 60%+ деградация сохранится — признак выводится из backlog'а
   кандидатов совсем.
4. Заявлений о статистической значимости нет (n=140, CI — описание
   неопределённости).
