# ADR-008 — Liquipedia как источник расписания для отображения + OpenDota live

**Статус:** Accepted — 2026-09-27. Владелец предоставил URL (`PGL/Wallachia/9`);
парсер реализован и протестирован на реальной фикстуре, live-конвейер проверен:
`/api/schedule/external` вернул матчи Group Stage с счётом и победителями.

## Контекст

Вердикт SRC-002: легального автоматического источника upcoming-расписаний нет —
работаем в ретроспективном контуре, расписание ведётся вручную (`scheduled_match`,
миграция 0004). Ночь 2026-09-27: владелец на реальных данных BB Streamers Battle 15
показал, что связка «Liquipedia (серии) + OpenDota /api/live (игры с `league_id`/
`series_id`)» решает задачу расписания без агентов и частых опросов. Проба интеграции
(`docs/research/SRC_003_LIVE_SCHEDULE_PROBE.md`) подтвердила с этой машины: OpenDota
live PASS; Liquipedia cargoquery отсутствует (SRC-002 верен), но `action=parse`
wikitext доступен.

## Предложение

1. **Liquipedia — display-only источник расписания**: парсер wikitext
   (`{{Match2}}`-шаблоны) по явному титулу страницы турнира, кэш 6–12 ч,
   ручное обновление в UI, attribution CC-BY-SA 3.0, интервал ≥2 c между
   запросами. В critical path модели НЕ входит — вердикт SRC-002 для модели
   остаётся действительным.
2. **Склейка по идентификаторам**: `league_id` + временное окно; `series_id`
   (пространство совпадает с нашими `series_key`) — ключ группировки игр
   внутри серии. Сопоставление по названиям команд запрещено (стороны
   меняются между картами).
3. **Условная частота**: расписание — кэш 6–12 ч; live-поллинг (≈1 мин) —
   только при наличии живой игры (`/api/live`).
4. **Fallback**: ручное расписание (0004) остаётся; оба источника в одной
   вкладке UI.
5. **Live-драфт** (`/api/live` → драфт игры) — отдельная вторая фаза,
   опционально; для Gate-2-данных достаточно ручного «Внести драфт».

## Последствия

- +1 внешний источник для UI (не для модели): деградация Liquipedia не
  влияет на прогнозы; fallback ручной.
- Attribution и rate-limit — обязательные условия, нарушение = отзыв ADR.
- Титулы страниц турниров конфигурируемы (не хардкод), угадывание не
  применяется.

## Приёмка

1. Парсер на сохранённом wikitext-фикстуре (тест без сети).
2. Кэш и attribution видны в UI.
3. Отказ Liquipedia → UI честно показывает «источник недоступен, введите
   вручную», ручные фикстуры продолжают работать.
