# ADR-006 — Порог приёмки модели фиксируется до обучения

**Статус:** Proposed. Требует решения владельца.

**Контекст:** владелец поставил цель «точность 70%» на target
`P(Team A выигрывает карту 1 | карта сыграна)`. Порог, выбранный **после**
того как метрика уже посчитана, перестаёт быть проверкой и становится
подгонкой. Нужен зафиксированный заранее порог и правило поведения при его
недостижении.

**Предложение:**

1. **Метрика:** accuracy на frozen test-сегменте — последний по времени блок,
   не участвовавший ни в обучении, ни в выборе модели. Дополнительно
   сообщаются log loss и интервал grouped bootstrap по сериям.
2. **Нижний ориентир (обязателен в любом отчёте):** `majority_class_accuracy`
   — точность константного прогноза. На срезе 2026-09-22 это **0.514**.
   Метрика модели ниже ориентира означает, что модель ничего не добавила.
3. **Порог: 0.70** — проектный, **заявленный владельцем до обучения**. Это
   **проверяемое условие, а не обещание**: оно не гарантируется и не должно
   достигаться подбором данных, сплитов или порога классификации.
4. **Правило при недостижении:** вердикт `insufficient evidence` или
   «порог не достигнут, значение X [интервал]». Модель **не** подгоняется до
   порога; допустимо менять признаки/модель только с новым, заранее
   зафиксированным прогоном и явной записью об этом.
5. **Статистика:** при n < 30 заявлений о значимости нет. Интервал
   grouped bootstrap — это грубая неопределённость, а не тест.
6. **Ограничение cutoff:** ретроспективный cutoff = `event_time` матча
   (времени объявления фикстуры у источника нет). Любой отчёт о метрике
   обязан указывать это.

**Текущие факты (срез 2026-09-22, 16 063 карты):**

| Показатель | Значение |
|---|---|
| Карт game1 в когорте | 3455 |
| train / valid / test | 3212 / 110 / 131 |
| Баланс меток | 0.514 |
| Нижний ориентир (константа) | **0.514** |
| Вердикт по test | объём достаточен для измерения (131 ≥ 30) |

70% означает **+18.6 п.п. над константой 51.4%** на pre-draft target без
состава и драфта. Это сильный результат, а не норма; ожидать его заранее
нельзя.

**Альтернативы:** (а) не фиксировать порог — тогда любая метрика станет
непроверяемой; (б) фиксировать порог по log loss или по lift над константой
(например, lift ≥ 5 п.п.) — более честно для несбалансированных когорт;
(в) отложить порог до ML-002.

**Последствия:** нужен frozen test, зафиксированный до обучения; нужны
manifest признаков/данных/кода; нужен запрет на подбор порога классификации
под метрику.

**Условия принятия:** владелец утверждает метрику, порог и правило при
недостижении до первого обучения (ML-001). Пересмотр — только с явной записью
причины и новой фиксацией до прогона.
