# ADR-010: доказательство полноты серии по внешнему подтверждению (Liquipedia)

**Статус:** Accepted — решение владельца 2026-09-27.
**Дата:** 2026-09-27.
**Связано:** ADR-006 (цель прогноза), ADR-008 (Liquipedia как источник
расписания), `normalize/map_index.py`.

## Контекст

`map_index.py` доказывает номер карты, только когда в серии карт ровно
`best_of`: пока карт меньше, нельзя исключить, что недостающая первая карта
просто не доехала из источника, и нумерация окажется сдвинутой. Правило
честное, но у него есть следствие, которое всплыло только на закрытии
Wallachia S9:

* серия Team Yandex — Natus Vincere: `best_of = 5`, завершилась **3:0**
  (три карты, 15:52 / 16:46 / 17:59 MSK);
* четвёртой и пятой карты не существует физически, значит `len == best_of`
  не достижимо **никогда**;
* серия вечно `incomplete`, `game.map_number` — NULL, и вердикт по заморозке
  `8987f801` (первый сбывшийся прогноз проекта) не сходится никогда.

То же ждёт любую bo5, завершённую 3:0 или 3:1 — то есть половину плей-офф.
Проблема не в терпении («подождать»), а в правиле: оно неразрешимо для таких
серий в принципе.

## Решение

Закрывать серию по **внешнему подтверждению**: Liquipedia (источник уже
принят ADR-008 для расписания) сообщает `finished` и счёт. Если число карт
серии в нашей БД **равно сумме счёта**, «недостающих» карт не существует —
серия полна, и номера карт доказуемы порядком старта (1..N).

Условия, при которых закрытие **допускается** (все сразу):

1. портал: матч `finished`, счёт парный;
2. пара команд портала == паре команд серии в БД (без регистра);
3. `best_of` портала == `best_of` серии;
4. `sum(score) == число карт серии в БД`;
5. победитель по счёту == победителю по нашим картам (число побед совпадает);
6. старт портала и время серии расходятся не более чем на 24 ч.

Не выполняется хоть одно — честный `skipped`, серия остаётся `incomplete`.
Цена ошибки — неверный номер карты, а значит неверный вердикт по заморозке и
мусор в обучающей когорте; поэтому проверки избыточны намеренно.

**Provenance.** Миграция `0006` добавила `series.closure_evidence` (JSONB):
кто подтвердил закрытие, счёт, формат, победитель, время наблюдения и правило
(`games_in_db == sum(score)`). Это provenance **решения**, а не наблюдаемый
факт; NULL означает «закрытие доказано по OpenDota» (старое правило, карт
ровно `best_of`). Снимки (`feature_snapshot`, `prediction_snapshot`) не
затрагиваются.

**Реализация:** `scripts/close_finished_series.py` — отдельный проход после
нормализации, идемпотентный, с `--dry-run`. Сознательно не встроен в
`normalize`: нормализация остаётся производной только от наблюдений
OpenDota, а внешнее подтверждение — отдельный шаг с собственной записью
provenance.

## Последствия

* `8987f801` получил вердикт: игра `d9dbec73`, `y=1`, `log_loss=0.5815`,
  `brier=0.1944` — первый prospective-прогноз подтверждён официально.
* Прогон закрыл 10 серий за последние 7 дней (50 пропущено: в портале нет
  завершённого матча с такой парой — он покрывает не все турниры).
* Карты закрытых серий становятся пригодны для когорты map1 (Gate-1).
* Зависимость: вердикт по bo5 теперь опирается на Liquipedia. Если портал
  недоступен, серия останется `incomplete` — это деградация, а не поломка, и
  она видна в `skipped`.

## Альтернативы

* **Оставить правило как есть.** Максимальная строгость, но вердикты по всем
  bo5 3:0/3:1 не сходятся никогда — прогноз без вердикта не даёт обратной
  связи, ради которой всё и затевалось. Отклонено владельцем.
* **Ослабить правило без внешнего источника** (считать полной, если карты
  идут подряд по времени). Не требует Liquipedia, но доказательство слабее:
  пропущенная ingest-ом первая карта незаметно сдвинет нумерацию.
* **Считать карты по `series_type` из OpenDota** — в ответе `/proMatches`
  формат есть, но факта «серия закончена» там нет, закрытие всё равно
  пришлось бы угадывать.
