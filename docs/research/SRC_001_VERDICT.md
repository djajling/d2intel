## 2. ИСТОРИЯ (OpenDota) — **PASS**

**Probe:** `GET https://api.opendota.com/api/proMatches` (без ключа).

**Результат:** HTTP 200, **86 записей** про-матчей.

**Поля записи (подтверждено):**

| Поле | Смысл | Значимость для d2intel |
|---|---|---|
| `match_id` | идентификатор матча | первичный ключ |
| `start_time` | unix-время начала | **база временной семантики / cutoff** |
| `radiant_team_id` / `radiant_name` | команда Radiant | identity resolution |
| `dire_team_id` / `dire_name` | команда Dire | identity resolution |
| `leagueid` / `league_name` | лига | **scope турниров** |
| `series_id` | идентификатор серии | **группировка карт в серию** |
| `series_type` | тип серии (BO3/BO5) | формат серии |
| `radiant_score` / `dire_score` | счёт | — |
| `radiant_win` | исход | **целевая переменная** |
| `duration` | длительность | фильтр несыгранных карт |

**Примеры лиг в ответе:** PGL Wallachia 2026 Season 9, WINLINE Star Series Season 4, NEXUS SERIES I, RES Unchained — A Blast Dota Slam IX Qualifier EU/SEA.

**Ограничения (по исходникам `odota/core` / `odota/web`):**

| Параметр | Free (без key) |
|---|---:|
| Дневной лимит | 3 000 |
| Минутный лимит | 60 |
| Цена | бесплатно |

**Важные замечания:**
- Прямого «номера карты в серии» (map index) в ответе **нет** — его нужно выводить из `series_id` + `start_time` (сортировка). Это подтверждает необходимость `DATA-001` и карантина неоднозначного map1.
- Некоторые записи имеют `null` в именах команд (стримерские/полупрофессиональные лиги) → нужна фильтрация по scope и обработка неполных identity.
- `/explorer` (SQL) даёт bulk-историю — использовать порциями из-за дневного лимита.

**Вердикт по истории: пригодна. Случай A не реализовался.**

## 3. UPCOMING — **не доступен бесплатным автоматическим путём**

**Probe 1 — OpenDota `/live`.** Валидный ответ, ~50+ записей. Поля: `activate_time`, `deactivate_time`, `league_id`, `game_time`, `match_id`, `series_id`, `team_name_radiant/dire`, `team_id_radiant/dire`, `players[]` (включая `hero_id`, `team_id`, `is_pro`).

**Но:** это **только идущие и недавно завершённые** лобби. Поля `activate_time` — в прошлом, `game_time` ≥ 0. **Будущих/запланированных матчей нет.** Расписания upcoming OpenDota не предоставляет — это совпадает с выводом `SOURCES.md`.

**Probe 2 — Liquipedia MediaWiki API.**
- `action=parse&page=Liquipedia:Upcoming_and_ongoing_matches` → REDIRECT на `Liquipedia:Matches`.
- `action=parse&page=Liquipedia:Matches` → страница существует (pageid 170781), но wikitext содержит **только вызов виджета**:
  ```
  {{#invoke:Lua|invoke|module=Widget/Factory|fn=fromTemplate|widget=Match/Ticker/Container|limit=50}}
  ```
- **Сами матчи подгружаются динамически.** Структурированных upcoming-данных в API-ответе нет.

**Probe 3 — LiquipediaDB API (v3).** Легальный путь к данным матчей, но:
- доступ **по одобренной заявке** (ручной шаг владельца);
- лимит 60 req/час, API key, нельзя передавать третьим лицам.

**Probe 4 — HTML-парсинг.** Проект `beeequeue/dota-matches-api` получает upcoming именно парсингом отрендеренной страницы. Это **запрещено** и ToS Liquipedia ("Automated access to non-API endpoints (ie, generated HTML pages) is not permitted"), и правилами d2intel. **Не рассматривается как путь.**

**Первичный вердикт по upcoming: автоматического бесплатного пути нет.** Единственный легальный вариант — LiquipediaDB API после одобрения заявки владельцем.

### 3.1 ПЕРЕСМОТР (дополнительный probe, тот же день)

Первичный вывод **оказался неполным** и пересмотрен. Проверка страниц **конкретных турниров** показала, что upcoming-матчи доступны как **статические `{{Match}}`-шаблоны в wikitext** через MediaWiki API — **без заявки и без ключа**.

Проверено: `PGL/Wallachia/9` и `PGL/Wallachia/9/Group Stage` (турнир 19–27 сентября 2026). Быстрый способ — `action=query&prop=revisions&rvprop=content&rvslots=main` (лимит 1 req/2 сек; `action=parse` — 1 req/30 сек).

Пример содержимого: `opponent1={{TeamOpponent|Team Yandex}}`, `opponent2={{TeamOpponent|Natus Vincere}}`, `date=September 21, 2026 - 19:00`, **`matchid1=9009924057`**, пики `t1h1..t1h5`, баны `t1b1..t1b7`, результат `length`/`winner`.

**Ключевое:** `matchid` совпадает с OpenDota → источники кросс-ссылаются.

**Ограничения:** команды в дальних раундах часто пусты (участники не определены) → по таким матчам система должна воздерживаться; нужен парсер wikitext; требуется User-Agent и атрибуция CC-BY-SA 3.0.

Детали: см. `LIQUIPEDIA_UPCOMING.md`.

**Уточнённый вердикт по upcoming: доступен легально через MediaWiki API.** Заявка на LiquipediaDB не обязательна для базового сценария (остаётся опциональным усилением).
