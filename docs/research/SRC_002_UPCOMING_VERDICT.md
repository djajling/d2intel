# SRC-002: upcoming/schedule — вердикт

**Дата:** 2026-09-23
**Автор:** агент (_session_, ветка аудита G-UPCOMING)
**Статус:** Proposed — вердикт для решения владельца

## Контекст

`SRC-001` вынес вердикт **B**: история работает, upcoming — no-go. Этот
аудит перепроверяет его в свете желания владельца тестировать модель на
живых матчах Wallachia S9. Проверка — bounded, read-only, без обхода
защиты: Cloudflare-блокировки зафиксированы как факт, а не как препятствие,
которое надо «обойти».

## Что проверено

| Источник | Метод | Результат |
|---|---|---|
| Liquipedia API (`action=help`, `query`) | чтение schema API | **нет match-list эндпоинта**: нет `cargoquery` (badvalue), список `query` содержит только стандартные MediaWiki-модули |
| Liquipedia `dota2dbapi` | чтение schema | **POST-only**, по конкретному `matchid` — это lookup матча, а не расписание |
| Liquipedia ToS | fetch | **HTTP 403** (Cloudflare human-verify) — лимиты/условия не прочитать программно |
| OpenDota `/proMatches` | fetch | **работает**, но возвращает **только сыгранные** матчи — upcoming'а там нет по построению |
| STRATZ GraphQL | fetch `api.stratz.com` | **HTTP 403** (Cloudflare) — из облачного агента недоступен; нужен тест с компьютера владельца |

## Вывод

**Вердикт B подтверждается.** Бесплатного легального источника расписания
upcoming-матчей по-прежнему нет:

- Liquipedia не предоставляет schedule через API — только парсинг wiki-страниц
  (хрупкий, под rate-limit'ом, ToS закрыт Cloudflare);
- OpenDota — только история, что мы и используем;
- STRATZ — закрыт для облачной проверки; проверить с компьютера владельца
  имеет смысл, если владелец готов завести API-ключ;
- PandaScore — бесплатный план даёт **fixtures** (расписание), но:
  1. исключён в проекте до письменного одобрения провайдера (betting-анализ);
  2. токен, присыланный в чате, скомпрометирован и подлежит ротации;
  3. live/драфт/история — платные планы, т.е. бесплатный план не закрывает
     всей желаемой функциональности.

## Что значит для продукта

Желаемая владельцем картина (live-матч → конец драфта → предикт + кефы)
 требует четырёх вещей, которых нет: upcoming-адаптер, live-драфт,
 автоматизация (запрещена без согласования), маркет-данные (только CSV от
 владельца). Это **не следующая задача**, а отдельный продуктовый этап с
 гейтами `G-UPCOMING` / `G-LIVE` / `G-MARKET` — каждый требует аудита и
 решения владельца.

## Рекомендация

1. **Не** строить upcoming-пайплайн сейчас. Нет источника → нет архитектуры.
2. Продолжить ретро-контур: `ML-001` LR-часть выполнена (см. handoff),
   следующие шаги — `API-001`, `UI-001`.
3. Если владелец хочет двигаться к live:
   - проверить STRATZ **со своего компьютера** (Cloudflare может пропускать
     браузерный/резидентный доступ) и завести API-ключ;
   - решить вопрос с PandaScore у провайдера (или отказаться);
   - после этого завести отдельную задачу `ING-004` с явным scope.
4. Live-тест на Wallachia возможен **только** как ручной prospective-прогон:
   владелец сообщает фикстуру заранее → агент строит предикт с
   `cutoff = now`, используя только `available_at <= cutoff` → маркируется
   `prospective_archived`. Это честно, не требует автоматизации и
   не нарушает временную семантику.
