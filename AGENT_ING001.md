## Задача: ING-001

**OpenDota-клиент + raw capture:** sync-once, pagination, retry, quota, idempotence.

**Зависимости:** `SRC-001` (завершён), `DB-001` (должна быть выполнена ранее — схема БД и таблицы для raw). Если `DB-001` не выполнена — **STOP**, сообщи об этом.

Приоритет P0.

### Что создать

Клиент-адаптер источника со следующими обязательными механизмами (по `ARCHITECTURE.md` §3):

1. **Объявление контракта источника:** `source_id`, `schema_version`, `capabilities`, `auth_mode`, `terms_reference`, `allowed_purposes`, `quota_policy`, `cursor semantics`, `timezone`.
2. **Bounded timeout** на запрос.
3. **Retry с exponential backoff + jitter** для transient failures; уважать `Retry-After`. Auth/permission errors — **остановка**, не бесконечный retry.
4. **Общий quota budget** по источнику для всех endpoints; журнал headers и кэш; **не провоцировать 429 намеренно**.
5. **Raw hash + request metadata**; возвращать batch с provider IDs, сырым payload, временем наблюдения, `retrieval status`, `next_cursor`, `completeness flags`.
6. **Pagination cursor + overlap window** для поздних исправлений; **watermark только после commit**.
7. **Idempotence:** natural-key uniqueness, transactional upsert; доставка at-least-once, обработка идемпотентная.
8. **Карантин** повреждённых строк с отдельной data-quality причиной; schema drift contract tests.
9. Source outage → **marked stale / fallback / abstain**; никакого тихого переключения на другой набор данных.

**Ключевое правило:** секреты, cookies и API-ключи **не сохраняются** в raw и log. Raw payload можно дедуплицировать по hash, но **повторные fetch observations и их времена сохраняются отдельно** — одинаковое содержимое на разных retrievals ≠ одинаковое событие получения.

### Карта API (проверено реальными запросами — см. `OPENDOTA_API_MAP.md`)

| Endpoint | Назначение | Примечание |
|---|---|---|
| `GET /api/proMatches` | обнаружение про-матчей | лёгкий режим, ~86–100 записей за страницу |
| `GET /api/explorer?sql=...` | bulk-выгрузка выборочных колонок | для таблиц `matches`, `picks_bans` |
| `GET /api/matches/{id}` | детальная информация | **точечно** — ответ очень тяжёлый |
| `GET /api/constants/patch` | справочник патчей | кэшировать, меняется редко |

**Лимиты free-tier:** 3 000 запросов/день, 60 запросов/мин, API key не требуется. Не тарифицируются HTTP 404/429/500. Читать `X-Rate-Limit-Remaining-Minute` / `-Day`.

**Проверенные колонки таблицы `matches`:** `match_id`, `series_id`, `series_type`, `leagueid`, `start_time`, `radiant_win`, `duration`, `game_mode`, `lobby_type`, `cluster`, `radiant_team_id`, `dire_team_id`.

**Проверенные колонки таблицы `picks_bans`:** `match_id`, `is_pick`, `hero_id`, `team`, `ord`.

**Важно:** `patch` **не колонка БД** (запрос вернёт ошибку) — вычисляется из `start_time` + `/constants/patch`.

### Acceptance criteria

1. Клиент объявляет контракт источника и возвращает batch с raw payload + metadata.
2. Throttle соблюдает 60/мин и дневной бюджет 3 000.
3. Retry с backoff/jitter, уважает `Retry-After`; auth-ошибки останавливают, а не ретраятся.
4. Idempotence: повторный прогон не создаёт дублей; watermark продвигается только после commit.
5. Карантин для проблемных строк с указанием причины.
6. Секреты отсутствуют в raw/log.
7. **Тесты зелёные**, в том числе: retry/backoff на моках, rate limiter, idempotence, карантин.

### Категорически НЕ делать

- **Не трогать временную семантику:** cutoff, as-of, snapshots. Ядро проекта — за ведущим архитектором. Клиент только доставляет сырые данные с временем наблюдения.
- **Не нормализовать** данные в канонические сущности и не вычислять feature (это `DATA-001` / `FEAT-001`).
- **Не вычислять map index** (номер карты в серии) и не связывать карты в серии — это `DATA-001`.
- **Не писать ML**, не обучать модели (`ML-001`).
- **Не использовать** `/api/live` для будущих матчей — upcoming-расписания в источнике нет.
- **Не выдумывать credentials**, не обходить ToS, не использовать HTML-scraping.
- **Не менять** `ARCHITECTURE.md`, `PRODUCT.md`, `BACKLOG.md`, `FIRST_10_TASKS.md`, ADR.
- **Не начинать** другие задачи.
