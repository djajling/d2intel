# D2INTEL — локальная рабочая область прогнозов

Адаптивный русскоязычный интерфейс, обслуживаемый FastAPI на `http://127.0.0.1:8000/`. Все счётчики, матчи, вероятности и оценки загружаются из локальной PostgreSQL через read-only dashboard API; демонстрационной вероятности или фиктивного календаря здесь нет.

## Возможности

- Поиск и постраничный просмотр завершённых первых карт серий с однозначными именами команд, датой, турниром и патчем.
- Расчёт Logistic Regression на выбранной исторической карте через существующий `POST /predict/game/{game_id}`. Перед отправкой пользователь подтверждает создание **нового неизменяемого снимка**; предыдущие снимки не перезаписываются.
- Журнал последних 100 снимков с живым поиском по команде, турниру и ID; фильтрами по режиму, наличию оценки и воздержаниям модели.
- Метрики log loss / Brier отдельно по ретроспективной и prospective-когорте; указывается число наблюдений с рассчитанными метриками. Это описательные средние журнала, а не frozen benchmark.
- Экспорт текущей выборки журнала в CSV с защитой текстовых ячеек от spreadsheet formula injection.
- Подробная карточка снимка: вероятности обеих команд (или явное воздержание без фиктивных нулей), UTC cutoff и время расчёта, идентификатор модели, алгоритм, схема признаков, snapshot признаков, фактический результат и сохранённые дифференциалы prior-form.
- Явное различение `retrospective_reconstructed` и `prospective_observed`.
- Цель прогноза зафиксирована вердиктом ADR-006 (2026-09-26): Gate-1 — pre-draft, карта 1; workbench показывает только game1 (`map_number = 1`). Неизвестный признак показывается как «Нет данных», а не как ноль.
- Компактная навигация для мобильного экрана, keyboard shortcut `/` для поиска, управление с клавиатуры, видимый фокус и `prefers-reduced-motion`.

## API-контракт

- `GET /api/overview` — summary данных, снимков, оценок и зарегистрированной baseline-модели.
- `GET /api/matches?limit=12&offset=0&search=...` — завершённые game1 с разрешённой идентичностью и известным результатом. Поиск безопасно параметризован.
- `GET /api/predictions?limit=100&offset=0` — неизменяемые snapshots, причина abstention и последняя оценка по исходу. Feature JSON загружается отдельным detail endpoint.
- `POST /predict/game/{game_id}` — существующий сервис сохранения нового снимка; новый read-only роутер не пишет и не меняет схему БД.
- `GET /health` и `GET /docs` — системный статус и OpenAPI.

## Временная семантика и известные границы

Кандидаты для нового расчёта — **завершённые исторические карты**. Их результат уже известен, поэтому новый расчёт — ретроспективная реконструкция, не прогноз «до матча». Интерфейс это повторяет рядом с действиями, в подтверждении и на каждой записи журнала. `prospective_observed` остаётся отдельным режимом для реально замороженных до события снимков; они не объединяются с ретроспективой.

Наличие обработчика модели в коде не гарантирует, что в текущей БД зарегистрирована пригодная `model_version` и доступен её локальный artifact. Если модель недоступна, UI отображает этот факт и отключает действие. Полный pre-match MVP заблокирован отсутствием проверенного бесплатного upcoming-источника; live, ставки, synthetic fixtures и заявления о прибыльности отсутствуют.

## Локальный запуск

Из корня репозитория выполните наблюдаемый локальный запуск, не останавливая и не меняя чужие службы/процессы:

```powershell
.\.venv\Scripts\python.exe -m uvicorn d2intel.app:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000/`; `/health` должен сообщить `database: up`. Если 8000 занят, сначала проверьте владельца существующего процесса — не запускайте второй сервер поверх первого вслепую. Статические файлы также видны без БД при прямом открытии `site/index.html`, но API-backed data в таком режиме работать не будет.

## Проверки

Dashboard API тесты используют memory session double и FastAPI TestClient — они не подключаются ни к рабочей, ни к выделенной PostgreSQL и не запускают destructive миграции:

```powershell
.\.venv\Scripts\python.exe -m pytest tests/api/test_dashboard.py
.\.venv\Scripts\python.exe -m ruff check src/d2intel/api/dashboard.py tests/api/test_dashboard.py
```

Остальной suite требует предусловий `AGENTS.md` / `REPO_SETUP.md`; в частности, migration/constraint тесты используют выделенную одноразовую БД, так как fixture делает `downgrade base`.
