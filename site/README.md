# D2INTEL — первый интерфейсный прототип

Статический интерактивный прототип первого экрана D2INTEL. Он отражает принципы из
[`../PRODUCT.md`](../PRODUCT.md), но использует **только демонстрационные данные**:
цифры не являются прогнозами и не должны использоваться для принятия решений.

## Что в прототипе

- карточка первой карты с наглядной вероятностью и статусом снимка;
- объяснимые факторы модели, форма и статус ростеров;
- журнал resolved/pending снимков;
- адаптивная вёрстка, сдержанные анимации и поддержка `prefers-reduced-motion`.

### Визуальный слой (текущая итерация)

- закреплённая шапка с размытием (`backdrop-filter`) для глубины;
- панели приподнимаются и подсвечиваются при наведении;
- карточки героев: имя и метка `DEMO` появляются при наведении/фокусе, мягкое свечение,
  не превращая интерфейс в «казино» (никаких поддельных боевых цифр или ставок);
- появление секций при прокрутке (`IntersectionObserver`, прогрессивное улучшение:
  без JS или при `prefers-reduced-motion` контент виден сразу);
- живой маркер вероятности и `aria-live` пояснение демонстрационного сценария;
- видимые состояния фокуса для клавиатуры, доступные строки журнала.

### Ассеты: политика и текущее состояние

Иллюстративные портреты героев берутся с публичного CDN Dota 2 в **вертикальной**
форме (`/apps/dota2/images/heroes/<hero>_vert.jpg`, 235×272). Раньше использовалась
широкая форма `dota_react/heroes/<hero>.png` (256×144) — при кадрировании в
вертикальную карточку 112×132 от героя оставалась только центральная полоса,
поэтому кадры выглядели обрезанными. Теперь пропорции карточки и ассета совпадают.

Эмблемы команд **намеренно не подгружаются с внешних CDN**: права не подтверждены,
а прежние источники (`gamesettings.top`, `img-cdn.hltv.org` — чужой CDN, отдавал 404)
неприемлемы. Вместо них рисуется монограмма (`TS`, `TF`) штатным механизмом fallback.
Перед релизом положить локальные файлы `site/assets/logos/*.png` с подтверждёнными
правами и вернуть `<img data-mono="…">` — в разметке оставлены комментарии с точным
шаблоном замены.

Механизм fallback остаётся: если внешнее изображение не загрузилось, `app.js`
заменяет его на монограмму — это чисто визуальный приём, он не добавляет данных.

## Разбор интерфейса (итерация «баг + полировка»)

Что было исправлено:

1. **Огромный зелёный овал поверх карточки матча.** Причина — CSS-специфичность:
   правило `.probability-track span { width: 62%; height: 100% }` было специфичнее
   `.probability-pulse { width: 9px; height: 9px }`, поэтому маркер вероятности
   растягивался до размера полосы (замерено 453×202 вместо 9×9) и превращался в
   залитую эллипсом кислотную область. Исправлено: правило сужено до `#probability-fill`,
   добавлена обёртка `.probability-track-wrap`, маркер вынесен из полосы. Проверено
   замером: маркер 9×9, центр совпадает с заливкой при любом положении слайдера.
2. **Обрезанные портреты героев** — см. раздел про ассеты выше.
3. **Битые/чужие логотипы команд** — см. раздел про ассеты выше.
4. **На мобильных полностью пропадала навигация** (`.nav { display: none }` при ≤800px),
   то есть на телефоне нельзя было перейти к «Журналу» или «Методу». Навигация возвращена
   второй строкой закреплённой шапки; шапка стала `height: auto` и переносит строки.
5. **Журнал на мобильных прокручивался горизонтально без визуальной подсказки.**
   Добавлено затухание правого края (`mask-image`) и тонкий скроллбар.
6. **Плашки пула героев теряли контраст** поверх светлой части портретов: фон был почти
   прозрачный (`rgba(255,255,255,.02)`), заменён на тёмный полупрозрачный с `backdrop-filter`.

Проверено (браузер, DOM-замеры): нет ошибок в консоли и `pageerror`; нет горизонтального
переполнения страницы на 375/1440 px; слайдер двигает и заливку, и маркер (проверено
на 40% — заливка 292px = 40%, цвет меняется на `hot` ниже 50%); обе монограммы на месте.

Замечено, но намеренно не менялось (кандидаты на следующую итерацию):

- горизонтальная прокрутка журнала на узких экранах — сознательная схема (таблица
  `min-width: 720px`), альтернатива — карточная раскладка строк на мобильных;
- декоративные портреты частично перекрывают строку команд — это задуманная глубина
  (`z-index: -1`), но при желании можно опустить `top` констелляции ниже плашек;
- дублирование шапки посередине full-page скриншота — артефакт съёмки `position: sticky`,
  а не дефект вёрстки.

## Локальный просмотр

Откройте `site/index.html` в браузере. Для дальнейшей разработки можно использовать
любой статический HTTP-сервер из каталога репозитория.

## Моковый контракт данных

Демонстрационные данные вынесены из разметки в [`site/match.snapshot.json`](./match.snapshot.json)
— первый моковый контракт в духе `PredictionSnapshot` / `FeatureSnapshot` из
[`../DATA_MODEL.md`](../DATA_MODEL.md). `app.js` загружает его (`fetch`) и заполняет
все секции: вероятность, уверенность модели, факторы-доказательства, пул героев,
форму, ростеры, журнал и блок **происхождения снимка** (snapshot id, computed/cutoff,
model version, feature snapshot, evaluation mode, sources). Это не «живой» прогноз:
поле `demo: true` и `evaluation_mode: retrospective_reconstructed` сохраняют статус
демонстрации.

Чтобы открыть страницу напрямую как файл (`file://`), в `index.html` продублирован тот же
JSON в `<script type="application/json" id="match-contract-fallback">`; при недоступности
`fetch` интерфейс берёт данные оттуда. При переходе на реальный API достаточно заменить
URL загрузки — форма ответа уже соответствует контракту.

## Замечание по спецификации (требует решения владельца)

Корневые документы (`PRODUCT.md`, `FIRST_10_TASKS.md`, `ARCHITECTURE.md`) описывают цель
как **первая карта, до драфта**, тогда как утверждённый [`docs/PRD.md`](../docs/PRD.md)
определяет цель как **карта N после полного драфта** с производной вероятностью серии.
Это противоречие не решается в визуальном прототипе: здесь по-прежнему показан
демонстрационный Game 1, и любой переход к контракту данных должен сначала согласовать
цель прогноза через ADR. Контракт содержит поле `target_note` с этим предупреждением.
